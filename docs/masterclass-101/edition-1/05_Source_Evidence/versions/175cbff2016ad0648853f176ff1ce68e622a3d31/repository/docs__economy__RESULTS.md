# CONTINUITY Ω — Results of the continuity economy experiment

[Français](RESULTS.fr.md) · [Setup and commands](README.md) · [Registered experiment](EXPERIMENT.md) · [Amendments](AMENDMENTS.md) · [Requirements and tests](REQUIREMENTS.md)

**The first registered experiment demonstrated accepted digital completion through primary recovery, an ordinary backup and an eligible alternative arrangement. It did not establish an advantage over the competent conventional method.** Both active methods obtained the same outcomes and modeled prices in all seven base comparisons. A separately funded technical control completed the digital product despite a rejected purchase. The capacity and uncertain-value controls correctly left obligations unfulfilled. These are distinct observations, not one success score. [B]

The later complete qualification reproduced those outcomes and completed a genuinely changed 1020-unit successor with both methods, using the unchanged frozen implementation. All 26 registered challenge assertions passed. The constrained capacity race still left 1400 of 1900 units missing, and a revoked-provider case completed the product while failing modeled economic participation. Those limits remain visible in the qualified result. [Q]

This report concerns a new, bounded **digital-product obligation** in version 0.2.0. Its substantive label-job content was produced, transferred, imported and inspected by disposable local processes. It establishes neither physical delivery nor authentic external customer acceptance, and does not strengthen historical v0.1 metadata receipts retroactively. All participant values, prices, funding, liabilities and outside options are authored synthetic assumptions. Modeled consent is not a real agreement, customer demand, payment or sale. [R]

### Feasible regions and boundaries

For price `P`, buyer value `V` and outside utility `U`, the modeled buyer condition includes `V ≥ P + U`, the maximum-price condition and available funding. A value interval `[L,H]` supports definite acceptability only when its lower bound satisfies the condition. Provider payment must cover base work, the full permitted correction financial allowance and the larger of required or outside-option profit; working funds and declared failure liability must also suffice. Financial provision for correction does not guarantee that later production capacity will remain available. [R]

For the constructed campaign, the relevant buyer break-even value is **7500 = 5500 + 2000** minor units. The intrinsic quotation floor of 7300 omits the earlier 200 coordination expense; it is not the campaign threshold. In `uncertain-value`, the 8300 price plus 2000 outside utility requires value at least 10300. The authored interval `[2000, 30000]` straddles that boundary, so consent remains `NOT_ESTABLISHED`. No favorable point was selected inside the interval. [B]

The technical control makes the distinction decisive: the buyer's authored value, price limit and funding were each only 100, with outside utility 2000. The 8300 trade was rejected. A sponsor separately incurred 4150, and the receiver still accepted the digital product. **A successful technical output did not create an acceptable trade.** [B]

## 5. What the comparison establishes

The conventional procedure enumerated the full bounded eligible assignment domain; the Harness procedure used branch-and-bound pruning over the same domain and tariff equations. Both received the same public contract, current funding, participant policies, capacity opportunities, observations, authorized actions, transactions, idempotency and reusable machinery. Both could restore the primary, use the existing backup or construct an eligible arrangement. The retained acceptance reference was hidden from both. [R, F]

All seven functional comparisons tied. The name `conventional-better` describes a better **conventional backup route**, which both methods selected. It is not an algorithmic victory over the Harness procedure. More broadly, the experiment evaluates two procedures using common recovery, execution and verification machinery; it does not isolate the entire product's value against an organization lacking that machinery. No actual AI comparison occurred. [B]
