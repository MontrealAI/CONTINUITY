# Validation history / Historique de validation

## English

This record preserves material development findings before the registered comparison. The immutable business specification stays at version 1. Engineering tests and preliminary controls are not counted as independent comparative trials. Unit-test temporary directories are disposable; retained experiment directories and logs are included in the delivery evidence where available. Missing logs are identified rather than reconstructed.

Three further surgical verifier mutations are intentionally run in the challenge suite. A passing adversarial assertion exposing false acceptance leaves the mutated checker's qualification **FAILED**. Their original target results and the correct reference results are saved separately. The actual implementation is restored after each scoped mutation.

The first 48-test independent-replay regression run had three errors in the test's mutation cleanup (`function.__code__`). Explicit restoration in a `finally` block corrected the test harness; the subsequent 48-test run passed. Both actual logs are retained. This correction changed neither the contract nor the verifier's acceptance criteria.

All later registered comparison attempts, including unsuccessful or incomplete ones, must remain separately named and reported. No unfavorable result authorizes a silent acceptance change. Preparation/integration labor was not timed; no development-effort, speed, cost or commercial improvement is inferred from these corrections.

Les tests techniques et contrôles préliminaires ne comptent pas comme essais comparatifs indépendants. Les répertoires temporaires des tests unitaires sont jetables ; les répertoires d’expérience et journaux conservés sont inclus dans les preuves livrées lorsqu’ils sont disponibles. Les journaux manquants sont signalés, jamais reconstitués artificiellement.

Trois autres mutations ciblées du vérificateur sont exécutées volontairement dans la suite contradictoire. La réussite d’un test exposant une acceptation indue laisse **ÉCHOUÉE** la qualification du vérificateur mutant. Les résultats originaux du composant et ceux de référence sont enregistrés séparément. L’implémentation réelle est rétablie après chaque mutation limitée à son appel.

La première exécution des 48 tests de reconstitution indépendante a produit trois erreurs dans le nettoyage de la mutation du test (`function.__code__`). Une restauration explicite dans un bloc `finally` a corrigé le dispositif de test ; l’exécution suivante des 48 tests a réussi. Les deux journaux effectifs sont conservés. Cette correction ne modifie ni le contrat ni les critères d’acceptation du vérificateur.

Chaque tentative comparative ultérieure, échouée ou incomplète comprise, doit rester nommée et rapportée séparément. Un résultat défavorable n’autorise jamais une modification silencieuse de l’acceptation. Le travail de préparation et d’intégration n’a pas été chronométré ; ces corrections n’établissent aucun gain d’effort, de vitesse, de coût ou de valeur commerciale.
