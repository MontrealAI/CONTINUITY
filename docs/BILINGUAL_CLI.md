# Bilingual command-line interface

**English** · [Français](BILINGUAL_CLI.fr.md) · [Repository home](../README.md)

`scripts/continuity.py` provides English and French help, errors, summaries and saved-record reports for the offline synthetic prototype. Python 3.10+ is sufficient. No package installation, network, credentials or real-world actions are needed.

## Quick start

Run from the repository root, choosing output paths that do not already exist:

```sh
python3 scripts/continuity.py --language en --help
python3 scripts/continuity.py demo --language en --case nominal --out /tmp/continuity-example
python3 scripts/continuity.py verify --language en --in-dir /tmp/continuity-example
python3 scripts/continuity.py inspect --language en --in-dir /tmp/continuity-example
python3 scripts/continuity.py inspect --language fr --in-dir /tmp/continuity-example
```

`--language en` is the default. `--language fr` selects French. The option works before or after the command, including with `--help`. Command names, option names, scenario identifiers, JSON fields, schema identifiers, hashes and verdict tokens are stable technical interfaces, not translated names.

## Three different operations

- **`demo`** runs the unchanged historical CLI against an authored synthetic scenario. It creates the original artifacts in a new `--out` directory, then uses the existing recorded-passport presenter to create **both** `PASSPORT.en.md` and `PASSPORT.fr.md` in a new sibling directory named `OUT-reports`. This includes constructor refusals: their reports explain `REJECTION.json`, not a nonexistent handoff. `--reports-dir NEW_DIRECTORY` selects another new report directory. Neither directory may contain the other. No existing output is overwritten. The original English `PASSPORT.md`, when generated by the historical CLI, remains unchanged.
- **`verify`** runs the unchanged historical checker now on `INPUT.json`, `HANDOFF.json` and `PASSPORT.json`. It neither reads nor updates `AUDIT.json`; its fresh result appears only on standard output. It does not apply the reader’s stricter presentation validation as extra audit rules. If input loading or the historical checker cannot complete, the wrapper reports a localized error without inventing a completed verdict. Malformed inputs that the checker can process retain its actual result.
- **`inspect`** uses the existing presenter to read the saved handoff/passport/audit records, or a saved refusal. It performs **no fresh audit**, does not read `INPUT.json`, and does not modify evidence. `--out /absolute/new-report.md` writes a new report outside the evidence directory. Unsupported records are refused rather than partly translated.

A fresh `verify` failure does not replace an older saved pass. A later `inspect` can still show that older pass, explicitly labeled as recorded. Keep the distinction when sharing either result.

## Other scenarios and machine-readable output

```sh
python3 scripts/continuity.py demo --language fr --help
python3 scripts/continuity.py demo --language fr --case overbooked --out /tmp/continuity-refused
python3 scripts/continuity.py verify --language fr --in-dir /tmp/continuity-example --json
```

The demo help explains every scenario in the selected language. `demo --json` prints the historical CLI’s original JSON result; bilingual report files are still generated. `verify --json` prints the fresh checker’s JSON result. These raw machine-readable outputs intentionally retain their original fields, tokens and prose, irrespective of `--language`. Errors remain localized on standard error. For saved machine-readable records, use the original JSON files; `inspect` is the human-readable view.

## Exit codes and file safety

- `0`: demo passed synthetically, verification passed synthetically, or inspection/report presentation completed. Inspection success is not an audit pass.
- `2`: constructor refused a demo, arguments or presentation were refused, or a local output operation could not complete. A refused demo can still produce a valid bilingual refusal report.
- `3`: a completed checker run returned `FAIL`, or verification could not complete. Read the message to distinguish a failed audit from absence of a fresh verdict.
- `130`: the operation was interrupted; completion is not confirmed.

Demo evidence is created before reports. If a later file operation fails, newly created files may remain incomplete. Preserve any evidence already written, inspect the paths and retry using new output paths. The wrapper does not silently delete partial results or replace historical records.

## Scope and historical preservation

This is a presentation interface, **not a checker repair or qualification**. The six `continuity_omega` source files, `scripts/continuity_passport.py` and `scripts/package_continuity_reading.py` remain byte-preserved. The original commands remain available for pinned historical reproduction:

```sh
python3 -m continuity_omega --help
python3 scripts/continuity_passport.py --language en --help
```

The prototype uses authored synthetic inputs. No real recovery, supplier commitment, customer acceptance, delivery, payment or external certification is established. The historical checker’s known weaknesses remain; separate code from the same research authors is not third-party assurance. This wrapper neither integrates nor qualifies the separately proposed PR #279 hardening.

## Tests

```sh
python3 -m unittest discover -s tests -p 'test_bilingual_cli.py' -v
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 scripts/verify_copy.py
```

The focused tests cover every scenario in both languages, byte-for-byte demo parity, both report files, help and errors, stable JSON, read-only inspection/verification, stale recorded verdicts, output collisions and partial-output failures. They test this interface, not the scientific adequacy of the historical checker.

The complete repository test suite (`python3 -m unittest discover -s tests -p 'test_*.py' -v`) additionally requires Node.js for website JavaScript checks. No npm packages are needed. The prototype and focused Python interface tests remain Python-only.
